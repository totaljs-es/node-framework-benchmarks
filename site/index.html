Read the full methodology ↗
01

Same runtime. Equal resource limits.

Node.js is pinned for all participants. Each scenario gets its own GitHub VM; its adapters run sequentially inside a container limited to 2 CPUs and 2 GiB RAM. Different scenarios can use different physical hosts.

02

Warm up. Measure. Let it settle.

Each measurement starts a fresh process: baseline, 15 s warm-up, 6 s settling, 60 s load and 30 s recovery. Three repetitions at 100 and 1,000 requested requests/s, with rotated adapter order.

03

Keep the limits in view.

The closed-loop load generator shares the container with the server. Requested traffic is a ceiling, not guaranteed arrivals. RSS is resident process memory, not live JavaScript heap. Hosted machines can vary between runs.

04

Follow every number to its source.

Download the original samples, exact package versions and verification receipt. Each campaign links to its source commit and workflow run. Smoke checks never enter the measurement history.
